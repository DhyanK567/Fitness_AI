Team doubts and answers

Q: What did we complete?
Only Syed and Yashwanth’s documented Day 1 SL + ERPE scope: API contract freeze, gateway foundation, database foundation, assigned Frappe DocTypes, health endpoint, and verification tests.
Q: Are we using Prisma and PostgreSQL?
Yes. Prisma defines and validates the PostgreSQL schema. PostgreSQL is the actual relational database. Prisma is the application schema and migration tool; it is not a replacement for PostgreSQL.
Q: Do we need a PostgreSQL API key from a website?
Not for local PostgreSQL itself. Local development uses a DATABASE_URL connection string. A hosted provider may give a password, connection string, pooler URL, or API key depending on that provider. We must use the provider’s documented credential and never commit it.
Q: Why are there tenant and audit protections?
The plan requires multi-tenant isolation and an audit trail. The migrations add tenant context helpers, row-level security, append-only audit protections, outbox events, idempotency keys, and webhook inbox foundations.
Q: Did we build frontend screens or AI features?
No. Those are outside this Day 1 handoff. AI remains P1 and no unrelated frontend or teammate-owned work was added.
Q: How do we prove it works?
The isolated folder passes 7 Python contract checks, 7 gateway unit tests, 1 gateway E2E test, Prisma validation, TypeScript compilation, and Python compilation.
Q: Where is the official work?
Fitness/Coding Work on branch feature/fitness-day1-sl-erpe. The PR is the review point; the old branch is not the pivot-work branch.
